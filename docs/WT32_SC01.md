# Wireless Tag WT32-SC01

This profile targets the original 3.5-inch WT32-SC01 with an ESP32-WROVER-B,
4 MB flash and 8 MB PSRAM. The WT32-SC01 Plus uses an ESP32-S3 and a parallel
panel bus, and requires a different profile.

## Hardware

| Part | Configuration |
|---|---|
| LCD | ST7796S, 320 × 480 native pixels, SPI at 40 MHz, BGR |
| SPI | SCLK GPIO14, MOSI GPIO13, CS GPIO15, DC GPIO21, reset GPIO22 |
| Backlight | GPIO23, active high, PWM dimming |
| Touch | FT6336U, ESPHome `ft63x6`, I2C address 0x38 |
| Touch bus | SDA GPIO18, SCL GPIO19, polled every 20 ms |
| Landscape | 480 × 320, 2 columns × 2 rows |
| Portrait | 320 × 480, 1 column × 3 rows |

The hardware pins follow the [original WT32-SC01 LVGL configuration](https://github.com/qiuxiaochao/WT32-SC01/blob/master/sdkconfig.defaults).
The drivers are ESPHome's [ST7796 MIPI SPI](https://esphome.io/components/display/mipi_spi/)
and [FT63X6](https://esphome.io/components/touchscreen/ft63x6/).
Touch stays in the panel's native coordinate space; LVGL rotates it with the
picture. A transform in an override must correct the raw panel coordinates only.

## Installation and flash space

Select WT32-SC01 in the board catalog, or use `packages/wt32sc01.yaml` from this
repository. A build from a clone uses `checkout/wt32sc01.yaml` with its own
`checkout/secrets.yaml` (see [checkout instructions](../checkout/README.md)).
The screen's own YAML must set `esphome.name`, Wi-Fi, API encryption and OTA credentials.
When testing a development branch, set both the package `ref` and substitution
`GITHUB_REF` to that branch so the packages, components and fonts agree.

This profile includes Tessera's existing wide 4 MB flash layout, retaining two
OTA slots of 2,031,616 bytes each. See [FLASH_LAYOUT.md](FLASH_LAYOUT.md) and
[UPDATING_4MB_SCREENS.md](UPDATING_4MB_SCREENS.md). Install over USB first if the
existing firmware cannot migrate its partition table. Increasing `flash_size`
beyond the physical 4 MB is not a solution to an oversized binary.

The compact look keeps the shared four-bit text fonts for smooth headings, tile
names and values. The large clock digits and back/status icons use two bits;
most other icons use one bit to save flash. All glyphs and controls are retained. Logging defaults to ERROR to retain failure diagnostics.
Enabling more logging in an override consumes additional flash space.
PSRAM is enabled for runtime memory. Camera pictures, snapshots and the larger
bedside digit font are intentionally omitted to limit firmware size. PSRAM does
not enlarge the OTA slots. Every firmware build still needs its size checked;
the wide table alone cannot fit a binary larger than a slot. The PSRAM profile allows up to 128 tiles across 24 pages and twelve top bar
items, subject to the runtime memory budget.

## Hardware acceptance

Support is experimental until checked on a physical board. Before using it for
daily control:

- Compile the checkout entry and confirm the binary fits the OTA slot.
- Check startup logs for 4 MB flash, detected PSRAM and FT6336U on I2C.
- Check red, green and blue, text direction and the whole display area.
- Tap all four corners and drag sliders; verify touch in landscape and portrait.
- Check dimming, standby, touch wake and page swipes.
- Connect to Home Assistant and save a four-tile page in Screen Manager.
- Restart and check saved settings, then test one OTA update.

A successful YAML validation or build does not prove any of these physical checks.
